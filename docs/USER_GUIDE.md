## 1. Требования и особенности запуска

- **Операционная система:** Windows 11 x64.
- **Права администратора:** приложение запрашивает повышение прав UAC (`requireAdministrator`), необходимое для монтирования WIM-образов через DISM и загрузки оффлайн-кустов реестра.
- **Свободное место:** рекомендуется не менее **40 ГБ** свободного места на диске с рабочей директорией (при меньшем объёме в интерфейсе отображается предупреждение).
- **Выбор файлов без Drag-and-Drop:** из-за политики безопасности Windows UIPI (User Interface Privilege Isolation) обычный Проводник не может перетаскивать файлы в окно приложения, запущенного от администратора. Выбор всех образов, пакетов, папок и скриптов выполняется через встроенные системные диалоги.
- **Сетевые пути и символические ссылки:** для безопасности сборки запрещены сетевые UNC-пути (`\\server\share\...`), пути устройств Windows (`\\.\...`), а также символические ссылки и NTFS junctions. Все исходные файлы и папки должны располагаться на локальных дисках.

## 2. Принцип работы: «Очередь изменений»

ISOCraft не держит образ постоянно смонтированным в режиме записи и не модифицирует исходный файл (`.iso`, `.wim`, `.esd`) на месте:

1. При выборе образа выполняется быстрая инспекция и однократное read-only чтение каталога выбранной редакции (с кешированием на диск).
2. Во всех остальных разделах вы формируете **очередь изменений** (какие Appx удалить/добавить, какие компоненты включить, какие обновления/драйверы/файлы/`.reg` интегрировать).
3. При нажатии **«Собрать образ»** запускается единый 9-шаговый пайплайн: он копирует/экспортирует рабочий образ во временную сессию, применяет всю очередь за один цикл монтирования и записывает результат по новому выходному пути.

## 3. Разделы приложения

### 3.1. Образ (`ImageScreen`)

- **Поддерживаемые исходники:** `.iso`, `.wim` (включая многофайловые образы с `.swm`) и `.esd`.
- **Строгая проверка образа:** допускается только **клиентская Windows 11 x64**:
  - `Architecture == x64`
  - `InstallationType == Client`
  - `build >= 22000`
  - Образы `boot.wim` / WinPE, Windows Server, Windows 10 и `x86` / `ARM64` автоматически блокируются с пояснением причины.
- **Выбор редакции:** в многоредакционном образе выбирается **одна целевая редакция** (например, *Windows 11 Pro*). При сборке экспортируется только этот индекс (`Index 1`), а остальные редакции вырезаются.
- **Загрузка каталога:** после выбора редакции ISOCraft читает списки Provisioned Appx, Optional Features и Capabilities. Результат сохраняется в дисковый кеш (`%LOCALAPPDATA%\ISOCraft\work\cache\catalog_*.json`). При необходимости каталог можно перечитать вручную кнопкой обновления.
- **Быстрые ссылки:** на экране доступны ссылки на официальную загрузку Microsoft Windows 11 и генератор образов UUP dump.

### 3.2. Приложения (`AppsScreen`)

Раздел управляет предустановленными пакетами **Provisioned Appx / MSIX** (пакеты, которые разворачиваются для каждого нового пользователя).

- **Удаление пакетов:** отмеченные приложения добавляются в очередь удаления по `PackageFamilyName` (чтобы пресеты оставались совместимы с более новыми версиями того же пакета в других сборках).
- **Защита критических компонентов:** системно-важные пакеты отмечены предупреждением, чтобы случайно не сломать Store, безопасность и зависимости приложений:
  - `Microsoft.WindowsStore`
  - `Microsoft.StorePurchaseApp`
  - `Microsoft.DesktopAppInstaller`
  - `Microsoft.SecHealthUI` (Безопасность Windows)
  - `Microsoft.Win32WebViewHost` и пакеты `WebView2`
  - `Microsoft.UI.Xaml*`, `Microsoft.VCLibs*`, `Microsoft.NET.Native*`, `Microsoft.WindowsAppRuntime*`
- **Добавление новых пакетов (`AddAppxModal`):**
  - Поддерживаются `.appx`, `.appxbundle`, `.msix`, `.msixbundle`.
  - **Зависимости:** при добавлении файлов или папки зависимостей ISOCraft автоматически отбирает совместимые с **x64** и **neutral** пакеты, отсеивая `x86` и `arm64`.
  - **Лицензия:** можно приложить файл лицензии `.xml` или включить `/SkipLicense` (по умолчанию включено).
  - **Дополнительные параметры:** `/Region:all` (по умолчанию включён) и `StubPackageOption` (`None`, `UseStub`, `UsePreference`).

### 3.3. Компоненты (`FeaturesScreen`)

- **Optional Features:** включение и отключение дополнительных компонентов Windows (например, `NetFx3` — .NET Framework 3.5, Hyper-V, Telnet Client и др.).
  - По умолчанию для включения передаётся флаг `/All` (включение родительских компонентов).
  - При работе с `.iso`-образом, содержащим `sources\sxs`, ISOCraft автоматически подставляет `/Source` из ISO и `/LimitAccess`. При необходимости можно указать собственную папку `sxs` (глобально или индивидуально для конкретного компонента).
- **Capabilities (FoD — Features on Demand):** добавление (`/LimitAccess` и при необходимости `/Source`) и удаление дополнительных возможностей (например, `OpenSSH.Client~~~~0.0.1.0`).

### 3.4. Обновления (`UpdatesScreen`)

- **Локальные пакеты:** можно добавить отдельные `.msu` / `.cab` файлы или целую папку.
  - **Windows 11 24H2+ Checkpoint CU:** если для установки накопительного обновления требуется базовое *Checkpoint Cumulative Update*, поместите оба `.msu` в одну папку (или добавьте вместе) — DISM передаст их пакетом/директорией и сам разрешит цепочку зависимостей.
- **Встроенный Microsoft Update Catalog (`CatalogModal`):**
  - Поиск по базе Microsoft Update Catalog (`Search.aspx`). Строка запроса автоматически подстраивается под ветку открытого образа (`21H2`, `22H2`, `23H2`, `24H2`, `25H2`, `26H2`), включён фильтр совместимости **Windows 11 x64** (исключаются Server, x86, ARM64, Dynamic Update и Windows 10).
  - Прямая HTTPS-загрузка `.msu` / `.cab` в `<workspace>\downloads\updates\` с отображением прогресса и возможностью отмены.
  - Каждый загруженный файл проверяется на **цифровую подпись Microsoft Authenticode** (`WinVerifyTrust`) и может быть сразу добавлен в очередь сборки.
- **Очистка хранилища компонентов (`StartComponentCleanup`):**
  - По умолчанию опция выключена. Если включена, выполняется `DISM /Cleanup-Image /StartComponentCleanup` **без `/ResetBase`** (чтобы не ломать последующую установку обновлений).
  - Если после интеграции компонентов или обновлений в оффлайн-образе есть отложенные операции CBS (код `0x800f0806`), очистка безопасно пропускается с предупреждением в журнале, не прерывая сборку.

### 3.5. Драйверы (`DriversScreen`)

- Добавление отдельных `.inf` файлов или папок с драйверами (поддерживается `/Recurse` для подпапок и `/ForceUnsigned` для неподписанных драйверов).
- Для каждого элемента выбираются целевые образы:
  - **`install.wim`** — драйверы для установленной Windows 11.
  - **`boot.wim` (Index 2 — Windows Setup)** — доступно при сборке ISO; необходимо для драйверов контроллеров накопителей (NVMe, Intel VMD, RAID), USB и сетевых адаптеров, чтобы установщик Windows видел диски на этапе разметки.

### 3.6. Реестр (`RegistryScreen`)

Позволяет применять `.reg`-файлы (форматов `Windows Registry Editor Version 5.00` и `REGEDIT4`, кодировки UTF-16LE/BE и UTF-8, размером до 64 МБ) напрямую к оффлайн-кустам образа без запуска `reg.exe`.

- **Очередь и порядок:** файлы можно включать/выключать и перемещать вверх/вниз по списку (применяются строго по порядку).
- **Dry-run предпросмотр:** перед сборкой отображаются затрагиваемые кусты, статистика операций установки/удаления, предупреждения, ошибки синтаксиса и первые 500 операций.
- **Маппинг веток в оффлайн-кусты:**

| Ветка в `.reg`-файле | Целевой оффлайн-куст в образе |
| :--- | :--- |
| `HKLM\SOFTWARE` | `Windows\System32\config\SOFTWARE` |
| `HKLM\SYSTEM\CurrentControlSet` | `Windows\System32\config\SYSTEM` (ветка из `Select\Current`, например `ControlSet001`) |
| `HKLM\SYSTEM\ControlSetNNN` | `Windows\System32\config\SYSTEM` |
| `HKLM\SECURITY` / `HKLM\SAM` | `Windows\System32\config\SECURITY` / `SAM` |
| `HKCU` (`HKEY_CURRENT_USER`) | `Users\Default\NTUSER.DAT` (профиль по умолчанию для новых пользователей) |
| `HKCR` (`HKEY_CLASSES_ROOT`) | `Windows\System32\config\SOFTWARE` → `Classes` |
| `HKU\.DEFAULT` | `Windows\System32\config\DEFAULT` |

- **Удаление защищённых ключей:** синтаксис `[-HKEY_...]` и удаление значений `"Name"=-` поддерживаются нативно через `REG_OPTION_BACKUP_RESTORE` и `NtDeleteKey` (обход прав `TrustedInstaller`).
- **Ограничения безопасности:**
  - Ветки `HKLM\HARDWARE`, `HKCC` и конкретные SID в `HKU\<SID>` пропускаются с предупреждением.
  - Значения `REG_LINK` (`hex(6)`) запрещены.
  - Запрещено удаление корней кустов, а также `HKLM\SOFTWARE\Classes`, `HKLM\SYSTEM\Select` и `HKLM\SYSTEM\ControlSetNNN`.

### 3.7. Файлы (`FilesScreen`)

Копирование произвольных файлов и папок в готовый образ:

- **Назначение (`target`):**
  - **Образ Windows (`install.wim`, корень `C:\`)** — доступно всегда. Быстрые пресеты: `Windows\Setup\Scripts`, `Users\Default\Desktop`, `ProgramData`, `Tools`.
  - **Корень ISO (`iso_root`)** — доступно при сборке в ISO. Быстрые пресеты: `sources\$OEM$`, `Soft`.
- **Автоподстановка пути:** при добавлении одиночных `.cmd` / `.bat` / `.ps1` автоматически предлагается `Windows\Setup\Scripts`, для остальных файлов — `Tools`, для папок — корень (`""`).
- **Политика конфликтов:** `Перезаписать` (`overwrite`) или `Пропустить` (`skip`) существующий файл.
- **Защита от повреждения системы:** нельзя перезаписывать кусты реестра (`Windows\System32\config*`, `Users\Default\NTUSER.DAT`) в `install.wim`, а также `sources\install.wim`, `sources\install.esd`, `sources\install*.swm`, `sources\boot.wim`, `boot\etfsboot.com`, `efi\microsoft\boot\efisys*.bin`, `bootmgr` и `bootmgr.efi` в корне ISO.

### 3.8. Сборка и пресеты (`BuildScreen`)

- **Пресеты (`.json`, `schemaVersion: "1.0"`):**
  - Сохраняют всю очередь изменений и настройки вывода (без привязки к исходному `.iso`/`.wim`).
  - При импорте проверяются все локальные пути (Appx, SxS, обновления, драйверы, `.reg`, файлы, `autounattend.xml`). Если какой-то файл был перемещён, появляется карточка **«Отсутствующие пути»** с кнопками **«Указать путь...»** и **«Удалить»**.
  - При импорте ISO-пресета поверх открытого `.wim`/`.esd` тип вывода автоматически переключается на `image`, а флаг инъекции драйверов в `boot.wim` сбрасывается.
- **Параметры вывода:**
  - **Контейнер:** `Загрузочный ISO` (только если исходник — `.iso`) или `Только install-образ`.
  - **Формат `install.*`:** `WIM` (быстрее, стандартное сжатие LZX) или `ESD` (максимальное сжатие `LZMS --solid`, занимает существенно больше времени).
  - **`autounattend.xml`:** автоматическая валидация структуры XML и отображение найденных проходов (`<settings pass="...">`).
  - **`sources\ei.cfg`:** добавление базового `[Channel] Retail / [VL] 0` для отображения выбора редакций при установке.
  - **Загрузчик UEFI:** `efisys_noprompt.bin` («без нажатия любой клавиши») или `efisys.bin`.
  - **Метка тома ISO:** очищается до допустимых ASCII-символов `[A-Za-z0-9_-]`, максимум 32 символа (по умолчанию `WIN11_CUSTOM`).
- **Во время и после сборки:** отображается 9-шаговый чек-лист и процент выполнения, доступна кнопка отмены (останавливает дерево процессов и выполняет `/Discard`), а после завершения — кнопка открытия файла в Проводнике и кнопка **«Экспорт диагностики»**.

## 4. Настройки, хранилище и обновления

Окно **Настройки** (иконка шестерёнки в заголовке) позволяет:

- **Рабочая директория:** изменить путь (по умолчанию `%LOCALAPPDATA%\ISOCraft\work`). Нельзя указывать корень диска (`C:\`), системные каталоги Windows, корни профиля/Program Files, сетевые UNC-пути, симлинки или менять папку во время активной сборки.
- **Управление хранилищем:** увидеть размер дискового кеша (`cache`) и скачанных обновлений (`downloads/updates`) и очистить их по отдельности.
- **Windows ADK `oscdimg.exe`:** указать путь вручную или использовать автопоиск. Принимается только бинарник с **подписью Microsoft Authenticode**, расположенный в защищённом каталоге (`Program Files`, `Program Files (x86)` или `%SystemRoot%`). Если `oscdimg.exe` не найден, используется встроенный `xorriso.exe`.
- **Обновления ISOCraft:** проверка новой версии на GitHub Releases и установка подписанного обновления с перезапуском (блокируется при активных операциях или незакрытых маунтах/кустах).
- **Язык и тема:** в заголовке окна доступны переключатель `RU | EN` и переключение темы `System → Light → Dark`. Размеры и развёрнутое состояние окна сохраняются автоматически.

## 5. Восстановление после сбоя и диагностика

- **Журнал сессии (`LogDrawer`):** открывается кнопкой **«Логи»** в нижней панели статуса. Поддерживает фильтрацию по уровню (`Все`, `Предупреждения`, `Ошибки`), текстовый поиск, копирование и экспорт диагностики.
- **Экспорт диагностики:** сохраняет единый файл, объединяющий журнал текущей сессии приложения и хвост `<workspace>\dism.log` (до 2 МБ).
- **Аварийное восстановление (`workspace_state.json`):** если программа была принудительно завершена или произошёл сбой питания во время монтирования, при следующем запуске появится баннер **«Обнаружена незавершённая рабочая сессия»** с кнопкой **«Очистить сейчас»**. Восстановление выгружает временные кусты реестра `ISOCRAFT_<pid>_*`, выполняет `/Discard` для зависших точек монтирования и запускает `DISM /Cleanup-Wim`.

## 6. Частые ошибки и их решение

| Симптом / код ошибки | Причина | Что делать |
| :--- | :--- | :--- |
| **`0x800f0993` / `0x80073712` / `0x800f0988` / `0x800f0982`** при установке обновлений | В Windows 11 24H2+ не хватает базового **Checkpoint Cumulative Update** в цепочке обновлений. | Поместите базовый Checkpoint `.msu` и целевой CU `.msu` в одну папку (или добавьте вместе) и добавьте в очередь целиком. |
| **`0x800f081e`** при интеграции `.msu`/`.cab` | Пакет обновления не применим к этому билду, редакции или архитектуре x64. | Проверьте версию сборки образа (например, `26100` — 24H2) и скачайте пакет именно для этой ветки Windows 11 x64. |
| **`0x800f0823`** при интеграции обновления | Требуется более свежий Servicing Stack Update (SSU). | Интегрируйте актуальный SSU или базовый Checkpoint/комбинированный пакет первым. |
| **Предупреждение `0x800f0806` на шаге очистки** | После включения компонентов или обновлений в оффлайн-образе есть отложенные операции CBS. | Это нормальное поведение: очистка автоматически пропущена, операции завершатся при первом запуске Windows. |
| **Выбранный `oscdimg.exe` отклонён** | Файл не подписан Microsoft или лежит вне защищённой папки `Program Files` / `Windows`. | Установите Windows ADK в стандартный каталог либо оставьте поле пустым для использования встроенного `xorriso.exe`. |
| **Баннер «Незавершённая сессия» / ошибка перед стартом сборки** | Остались незакрытые WIM-маунты или кусты реестра в `workspace_state.json`. | Нажмите **«Очистить сейчас»** на баннере (или закройте все окна Проводника/терминалы, удерживающие файлы в `session_current`, и повторите). |
| **Ошибка UNC-пути / символической ссылки** | Исходник, рабочий каталог или вложения находятся на сетевой шаре или используют symlink/junction. | Перенесите файлы на локальный NTFS-том по обычному пути без симлинков. |
