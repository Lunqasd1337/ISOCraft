# Дорожная карта ISOCraft

Этот документ описывает запланированные направления развития **ISOCraft** поверх текущей архитектуры («Очередь изменений», чистое ядро `isocraft-core`, нативный оффлайн-реестр и 9-шаговый пайплайн сборки). Задачи сгруппированы по приоритету внедрения.

---

## Приоритет 1 — Ключевые сценарии

- [x] **Экспорт драйверов с текущего ПК и управление драйверами образа**
  - Экспорт установленных драйверов с хоста (`dism /Online /Export-Driver`) с фильтрацией по классам устройств (`Storage`/`NVMe`, `Net`/`Wi-Fi`, `Display`, `Audio` и др.) и автоматическим добавлением в очередь `install.wim` / `boot.wim`.
  - Просмотр сторонних драйверов, уже интегрированных в выбранную редакцию (`Get-WindowsDriver`), и выборочное удаление устаревших пакетов из образа.

- [x] **Конструктор постустановки (Post-Setup)**
  - Поддержка двух фаз выполнения: **Before Logon (`SYSTEM`)** через `Windows\Setup\Scripts\SetupComplete.cmd` и **First Logon (User)** через `RunOnce` в `Users\Default\NTUSER.DAT` или `FirstLogonCommands` в `autounattend.xml`.
  - Очередь тихих установщиков (`.exe`, `.msi`) с заданием аргументов запуска и автоматической очисткой временных дистрибутивов после установки.
  - Генератор команд автоматической установки приложений через `winget install` при первом входе в систему.
  - Упорядоченная очередь пользовательских скриптов `.ps1` / `.cmd`.

---

## Приоритет 2 — Продвинутое обслуживание образа

- [x] **Оффлайн-менеджер служб Windows (`Services`)**
  - Чтение служб из `SYSTEM\ControlSetNNN\Services` на этапе инспекции образа и изменение типа запуска (`Automatic`, `DelayedAuto`, `Manual`, `Disabled`) через нативный Win32-движок `registry.rs`.
  - Цветовые уровни риска и защита критических системных служб (RPC, DHCP, Windows Update, Security Center и др.) от случайного отключения.

- [ ] **Обслуживание `boot.wim` и `winre.wim` и обход требований в `boot.wim`**
  - Прямая запись ключей `HKLM\SYSTEM\Setup\LabConfig` (`BypassTPMCheck`, `BypassSecureBootCheck`, `BypassRAMCheck` и др.) в `boot.wim` (Index 2) через `registry.rs` — работает без обязательного `autounattend.xml` и не конфликтует с внешними средствами записи USB.
  - Применение Safe OS Dynamic Updates к `winre.wim` и обновлений безопасности к `boot.wim` в рамках пайплайна сборки.

- [ ] **Безопасное удаление Win32-компонентов (OneDrive, Recall, политики Edge)**
  - Удаление `OneDriveSetup.exe` и записи автозапуска `OneDriveSetup` из куста `Users\Default\NTUSER.DAT`.
  - Отключение **Windows Recall** штатными средствами (DISM Feature / групповые политики) без деструктивного вмешательства в `WinSxS` / CBS.
  - Опциональные политики отключения автозапуска, рекламных элементов и боковой панели Microsoft Edge.

- [ ] **Языковые пакеты и региональные настройки оффлайн-образа**
  - Интеграция Language Packs (`.cab`) и Local Experience Packs (LXP).
  - Настройка системной локали, раскладок клавиатуры и часового пояса оффлайн-образа (`DISM /Set-AllIntl`, `/Set-TimeZone`, `/Set-InputLocale`).

- [ ] **Хеш-суммы, отчёт сборки и утилиты для контейнеров**
  - Вычисление `SHA-256` для исходного образа и собранного итогового файла.
  - Итоговая карточка отчёта после завершения сборки: сравнение размера («было → стало»), затраченное время и сводка реально применённых изменений.
  - Опциональное оффлайн-обновление редакции (`DISM /Set-Edition`) и опциональное разбиение `install.swm` (`< 4 ГБ` для носителей FAT32 через `wimlib-imagex split`).

## Приоритет 3 — Автоматизация и экосистема

- [ ] **Headless CLI (`isocraft-cli`)**
  - Консольная обёртка поверх `isocraft-core` (`isocraft-cli build --source ... --edition ... --preset ... --output ...`) для автоматизированного запуска сборок по расписанию (Patch Tuesday) и в CI-пайплайнах.

- [ ] **Портативные бандлы пресетов**
  - Экспорт и импорт самодостаточных архивов (`.isocraft-bundle` / `.zip`) или поддержка относительных путей рядом с JSON-пресетом для переноса сборок между компьютерами без ручной перепривязки файлов.

- [ ] **Удобная проверка и перенос результата (Ventoy / VM)**
  - Быстрое копирование готового ISO на подключённый съёмный том Ventoy с проверкой контрольной суммы.
  - Генерация вспомогательного `unattend.iso` и быстрый запуск или шаблон проверки собранного образа в виртуальной машине (Hyper-V / VMware / QEMU).
